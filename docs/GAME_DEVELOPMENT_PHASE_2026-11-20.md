## 四款游戏的本阶段工作包

### 1. 刀域突围 3D（`game3d/`）

目标：从“职业展示/攻击特效”进一步走向可感知的战斗差异。

- 审核十种职业的攻击输入、攻击判定、冷却、动作反馈与数值边界。
- 核对武器熟练度、职业熟练度、每日委托、首领战统计是否重复计数或相互矛盾。
- 设计并实现至少一组可验证的敌人/首领行为差异，而不是只增加血量。
- 验收：职业动作不串线；攻击和命中反馈一致；首领状态变化可观察；存档异常不阻断战斗。

### 2. 回声 ECHO（`echo2d/`）

目标：把新增玩法从“参数面板/档案”推进为真正可玩的声学谜题。

- 审核主线关卡、主题关卡、共振阵列、多频解码、空间音频试炼之间的规则一致性。
- 为新增谜题建立确定性答案校验与边界测试，检查是否存在无解、误判或跳关。
- 优化提示与失败反馈，让玩家知道错在频率、相位、谐波还是噪声，而不是只给分数。
- 验收：每关有唯一或明确允许的答案范围；重试/重置/刷新恢复一致；静音环境下仍有可理解的视觉反馈。

### 3. 衍尾之宙 NEXUS（`nexus/`）

目标：让证据、推理、反证和章节结论构成可追溯的案件闭环。

- 审核主线卷宗与证据总账、证据关系、因果链、证词矛盾、时间线模块的真实数据接口。
- 区分“已发现线索”“支持命题”“排除命题”“仍未知”，避免把线索数量误当成推理正确。
- 检查章节解锁、答题保存、反证反馈与结案条件是否一致。
- 验收：结论能追溯到证据；错误推理有具体反证；刷新后答案和章节状态稳定；不自动替玩家补全推理。

### 4. 夜班群聊 · 未读消息（`rulechat/`）

目标：强化多会话叙事的连续性与选择后果。

- 审核主线、长篇特别章、聊天生活模块、取证台之间的章节/联系人/消息状态。
- 检查选择分支是否产生可见且持久的后果，避免只改变一行文本。
- 检查未读数、会话顺序、消息时间、附件/语音卡片和章节回放的状态一致性。
- 验收：选择影响后续消息或线索；刷新恢复不重复、不丢失；长篇章节完成后可重开；缺失资源有明确降级。

## 执行规则

1. 每次只改一个游戏的一个清晰工作包；完成后再进入下一款，避免四款同时大面积改动。
2. 开工前读取目标模块、入口加载顺序、存档键和相关调用点；不得仅凭旧报告猜测接口。
3. 优先新增独立模块或最小补丁；不重写大型主文件，不更换现有存档命名空间。
4. 每个工作包必须包含：代码实现、静态语法检查、针对性逻辑断言、变更记录及未完成风险。
5. 代码通过静态检查不等于浏览器/手机验收；没有真实设备证据时明确标记“待实机验收”。
6. 不虚构图片、音频、模型或在线多人能力；占位内容必须明确标记。
7. 未经用户明确要求，不合并到 `main`，不触发正式部署。

## 2026-11-20 · 回声 ECHO 第一项修复

文件：
- `echo2d/resonance-circuit.js`
- `echo2d/sw.js`

问题：
- 共振阵列此前把任意分数的分析记录都计入“六段解码记录已齐全”，低分记录也可能被误认为完成。
- 读取存档时只做 JSON 解析，没有验证结构、关卡索引、分数和评级。
- 写入共振阵列存档没有捕获 localStorage 异常，存储受限时点击分析可能抛错。

修复：
- 增加独立的已校准关卡集合；只有匹配分数达到 88% 才记为有效校准。
- 最佳分数仍可保留低分尝试，但低分不会冒充完成进度。
- 读取时校验关卡索引、分数范围和评级格式；非法记录忽略。
- 存档写入失败时捕获异常并记录警告，不中断当前分析流程。
- 面板显示“已校准/待校准”和有效总进度。
- Service Worker 缓存版本更新为 `echo2d-v62-0-6`。

验证：
- 更新后的 `resonance-circuit.js` 与 `sw.js` 均通过 V8 `new Function` 语法解析。
- 已确认完成判定使用有效校准集合，而非“有记录的键数量”。
- 尚未执行浏览器实际调参、刷新恢复、禁用 localStorage、手机音频播放测试；这些仍标记为待实机验收。
